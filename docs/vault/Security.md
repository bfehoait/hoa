Broad legacy member/shared JSON reads and legacy admin writes must be replaced/coordinated before claiming full backend isolation. The matrix still needs field-level privacy decisions, assigned-work enforcement, export/file rules, business approval workflows and Super admin definitions. No browser feature substitutes for those server controls.

## Developer module monitoring

Migration 002 prepares a read-only SECURITY DEFINER function with a fixed search path, explicit developer check, bounded pagination and a source/field allowlist. It accepts no arbitrary SQL/table selection and changes no existing policies. The field projection omits password/token/proof fields and nested objects; election rows are restricted to setup metadata. It exposes neither raw ballots nor Auth user secrets. Free-text fields are not semantically redacted: legitimate operational descriptions can contain personal information, so this remains privileged read access, not a public directory or a certification of source authenticity.

The direct developer shell remains separate from role-preview identity overrides. Admin without developer is rejected by the monitor function. Direct operational actions remain governed by separately assigned roles and their protected endpoints. A revoked developer assignment is checked again by the server; query failures hide previous rows instead of substituting samples. Privileged-read auditing, legacy JSON scalability, private file access and a global real-time event stream remain separate work. Local PostgreSQL tests exercise only the new function and synthetic source schemas, not the deployed project.

**Auth implementation, 5 November 2026** - Real sign-in is opt-in through supplied connection values and otherwise remains disabled. Authenticated mode is the default; preview requires an explicit build setting. Supabase SDK handles password sign-in, PKCE recovery, refresh and current-session sign-out. `getUser` verifies identity before member lookup, which selects only required columns using the verified user ID. Membership failure denies access. Route gates normalize encoded paths; return URLs are limited to allowed internal pages. No live database or policy verification was performed. MFA and operation-level backend enforcement remain separate release requirements. Membership polling does not replace server refusal checks.
